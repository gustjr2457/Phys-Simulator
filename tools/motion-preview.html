디자인은 지금 그대로 두고 움직임만 바꿨습니다. 아래 버튼으로 바꿔 가며 화면 안의 앱을 직접 눌러 보세요. 세 예시는 순서대로 쌓입니다 — B는 A를, C는 B를 포함합니다. 기준은 하나입니다. 자주 보는 것은 움직이지 않고, 드물게 보는 것에만 움직임을 쓴다.

무엇을 바꿨나

예시이전이후이유
Atransition:.12s 13곳바뀌는 속성만 명시 — background-color, border-color, color, transform.12s는 사실상 transition: all이다. 의도하지 않은 속성까지 움직인다.
A누름 피드백 없음 (재생 버튼만 배경색 변화):active { transform: scale(.97) } 160ms, 큰 카드는 .99인터페이스가 눌렀다는 걸 들었다고 답해야 한다. :active는 마우스·터치로만 걸려서 Space/R 단축키에는 자동으로 움직임이 없다.
A기호에 마우스를 올리면 밑줄 2px → 3px밑줄은 2px 고정, 굵어지는 효과는 box-shadow로테두리 굵기 변화는 레이아웃을 바꾼다. 공식 줄이 1px씩 들썩이던 원인이다.
A슬라이더 손잡이: 마우스를 올리면 height 16 → 18px잡았을 때만 scaleY(1.18), 120ms가장 자주 만지는 조작이라 아주 작게. height 대신 transform.
Aprefers-reduced-motion 처리 없음위치·크기 변화만 빼고 색·투명도는 남김움직임 줄이기는 "0"이 아니라 "덜"이다.
B모달 2개가 display:none 토글로 순간 등장·소멸열림 220ms scale(.97)→1 + 불투명, 닫힘 140ms가끔 여는 것이라 표준 전환 대상. 닫힘(시스템의 응답)이 열림보다 빨라야 한다. 화면 중앙에 뜨므로 원점도 중앙.
B—Esc로 닫을 때는 전환 없음키보드 동작은 애니메이션하지 않는다. 같은 모달이라도 클릭으로 닫을 때만 움직인다.
B힌트가 툭 튀어나옴위에서 4px 내려오며 나타남 180ms, 사라짐 120ms순간 등장은 깨진 것처럼 보인다. 높이는 건드리지 않고 transform·opacity만.
C과제 달성 시 테두리 색만 바뀜처음 달성한 순간에만 배지 반동 420ms + 초록 띠가 훑고 지나감 700ms세션에 과제당 한 번뿐인 드문 순간 — 즐거움을 줘도 되는 유일한 곳. 열자마자 이미 만족된 과제는 사용자가 한 일이 아니므로 축하하지 않는다.
C목록이 한꺼번에 나타남처음 열었을 때만 35ms 간격으로 차례로, 260ms분류를 바꿀 때마다 반복하면 하루 수십 번 기다리게 된다. 첫 방문에만.

일부러 움직이지 않게 둔 곳

  • 시뮬레이션 전환 — 패널 내용이 순간 교체됩니다. 하루 수십 번 하는 목록 탐색이라 탈락.
  • Space 재생 / R 처음으로 — 키보드 동작, 하루 수백 번. 절대 애니메이션하지 않음.
  • 프리셋을 누르면 슬라이더가 미끄러져 이동 — 그럴듯하지만, 시뮬레이션은 이미 새 값으로 다시 시작했는데 손잡이만 늦게 따라오면 보이는 값과 실제 값이 어긋난다. 탈락.
  • 측정값 숫자 롤링 — 사용자가 읽고 있는 데이터는 꾸밈 때문에 움직이면 안 된다. 탈락.
  • 기호 설명 문구 교체(공식에 마우스 올림) — 하루 수십 번, 탈락. 높이를 미리 확보해 둔 지금 방식이 이미 맞습니다.
